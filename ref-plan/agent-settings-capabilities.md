# Agent 与 Models 设置原型能力清单

## 1. 目标与边界

目标：让用户通过图形界面完整管理 OMP 的 Agent 定义、Agent 运行设置、模型服务、模型角色和默认模型，不必为了常规配置返回 TUI 或手写配置文件。

本清单以项目当前使用的 **OMP 18.12.6** 为基准，面向原型设计，只描述需要哪些界面、可编辑什么、必须表达哪些状态；不规定实现架构，也不代表现有应用已经具备这些能力。

需要区分三个对象：

| 对象 | 解决的问题 |
| --- | --- |
| Agent 定义 | 有哪些子代理、适合什么任务、提示词是什么、能使用哪些工具、默认用什么模型 |
| Agent 运行设置 | 主会话与子任务如何执行，包括审批、上下文、工具、记忆、并发、隔离等 |
| Models 配置 | 有哪些模型服务和模型，各用途角色选哪个模型，以及认证、思考、候选与故障转移策略 |

“与 TUI 一样完备”应覆盖 `/settings`、`/agents`、`/models`、模型预设及相关认证、顾问配置入口。原生配置文件支持但 TUI 没有专门表单的能力，也需要有结构化编辑或高级配置入口，不能只复刻当前原型中的几个通用键值框。

## 2. 所有界面共同需要的配置上下文

### 2.1 作用域与来源

设置入口必须明确当前容器、OMP profile、项目路径，以及本次操作的保存位置。这里的“全局”是**当前容器、当前 OMP profile 的用户配置**，不是开发机配置，也不是跨容器共享配置。

| 配置对象 | 原型必须表达的作用域与限制 |
| --- | --- |
| Agent 定义 | 支持项目和用户级定义；项目通常使用 `.omp/agents/`，用户级通常使用 `~/.omp/agent/agents/`；内置和插件定义另标来源 |
| 模型角色绑定 | 支持全局和项目；`modelRoleStorage` 决定原生角色编辑的保存位置，项目角色写入 `.omp/config.yml`，未设置的项目角色继承全局 |
| 普通运行设置 | 原生常规设置写入全局配置；项目配置也能参与读取和覆盖，编辑项目层时必须指向真实配置源，不能假称切换角色存储范围就切换了全部设置 |
| 模型服务与自定义模型 | 默认读取当前 OMP 配置目录的 `models.yml`；不能承诺会自动加载项目下的 `.omp/models.yml` |
| 模型预设 | 原生保存、删除操作面向全局；项目文件可定义预设并参与列出和应用，修改这类预设应定位其源文件 |
| 认证与账号 | 属于独立凭据存储；不能因选择项目范围就将密钥、OAuth 数据或认证代理连接写进项目 |
| 当前会话模型 | 可以仅临时切换；必须与持久化的角色绑定、默认模型分开 |

路径以当前 OMP 实际解析结果为准，兼容 profile、XDG 和目录覆盖，不把上表中的常见路径写死为唯一位置。

### 2.2 保存值与有效值

- 同时表达“本层设置了什么”“最终生效什么”“由哪一层决定”；详情中可以查看默认、全局、项目、启动配置覆盖、运行时覆盖和适用的环境变量来源。
- 普通设置通常按环境变量、运行时覆盖、`--config` 覆盖、项目、全局、默认值的优先关系解析；部分环境变量只是兜底，不能一律视为最高优先级。
- Agent 同名定义是**整份覆盖**，不是逐字段合并；不能与普通设置的层级合并画成同一种行为。
- “清除当前层覆盖”“恢复继承”“设置为默认值”“删除定义”是不同操作。保存成功但仍被上层覆盖时，要显示真实结果。
- 作用域不适用的操作应禁用并解释，不能静默写到另一个位置。

## 3. 原型需要包含的界面

以下是逻辑界面，不要求全部成为独立全屏页面；简单选择可用弹层，长文本、复杂对象和完整定义适合详情页。

### 3.1 Agent 设置总览

- 提供 Agent 管理、默认模型与角色、模型服务、模型预设、故障转移、运行设置、高级配置入口。
- 可按中文名称、原生配置键和当前值搜索，支持仅看已修改项。
- 显示当前配置上下文；返回后保留搜索、滚动和展开状态。
- 提供单项、分组和当前可编辑范围的重置，不把“重置 Agent 设置”误做成清空账号或删除全部模型服务。

### 3.2 Agent 列表与来源详情

- 浏览、搜索项目、用户、内置及扩展包提供的 Agent；列表显示名称、用途、启用状态、模型绑定概况。
- 详情显示真实文件路径、所属包、胜出的定义和被遮蔽的同名定义。
- 支持启用、禁用，以及进入定义编辑和运行覆盖设置；禁用按 Agent 名称生效，不只是隐藏某个文件。
- 支持复制到项目或用户范围后修改；删除用户可编辑定义前，预览删除后是否会重新露出低优先级同名定义。
- 内置和包内定义按只读来源展示，不直接修改安装包；通过自定义副本覆盖，或清除覆盖恢复下层定义。
- 项目发现使用从当前目录向上找到的最近一个 `.omp/agents/`，不是合并每一级目录。新建时明确实际写入目录，不能把“发现目录”和“新建目标目录”混为一谈。
- OMP 扩展 Agent 与兼容插件 Agent 需要保留来源差异；不能把其他工具的任意 Agent 目录直接宣称为 OMP 可用来源。

### 3.3 Agent 新建、编辑与预览

需要手工编辑完整定义，同时保留原生“描述需求 → AI 生成 → 预览 → 选择项目或用户范围 → 保存”的创建流程。AI 生成是真实模型调用，需要显式触发、加载、失败、重新生成与取消状态。

| 编辑分区 | 必需能力 |
| --- | --- |
| 基本信息 | Agent 标识 `name`、用途 `description`；保留名校验；显示保存路径和同名覆盖关系 |
| 系统提示词 | 编辑 Markdown 正文并预览；长内容全屏编辑，不把它当作普通单行设置 |
| 模型 | 编辑 `model` 的有序候选列表，支持具体模型、角色引用和原生选择器；设置 `thinkingLevel`，区分继承与显式选择 |
| 工具 | 编辑 `tools`；区分未设置时采用默认工具与显式空列表，不因解析错误放开限制 |
| 下级派发 | 独立编辑 `spawns`：默认行为、所有 Agent 或指定列表；展示其与工具列表、最大递归深度的关系 |
| 技能 | 编辑 `autoloadSkills`，从实际已发现技能中选择，并提示无法解析的名称 |
| 输出 | 编辑 `output` 输出 Schema 与 `structured`；结构化结果不是普通提示词文本 |
| 执行 | 编辑 `blocking`，表达为该类任务是否阻塞等待，不误称为禁止一切后台执行 |
| 读取摘要 | 编辑 `readSummarize`；关闭可禁用摘要，不能把开启描述为强制覆盖父级的禁用设置 |
| 模型切换与审查 | 编辑 `prewalk`、`advisor`，支持默认、关闭、启用默认目标或显式模型目标 |
| 原始定义 | 可切换 YAML frontmatter + Markdown 编辑，保留未识别字段，不因表单未覆盖而丢失原配置 |

补充语义：`prewalk` 不是“起始模型”；它是在满足条件后的首次编辑或写入时切换执行模型。工具选择也不是完整安全沙箱，不能承诺隔离所有 MCP、扩展或自动补充工具。

### 3.4 每个 Agent 的运行覆盖设置

此页编辑的是设置中的覆盖项，不是改写 Markdown 定义。必须显示“定义默认 → 当前层覆盖 → 有效结果”，并支持清除单项覆盖。

- 启用或禁用：`task.disabledAgents`。
- 模型覆盖：`task.agentModelOverrides`，支持有序候选与思考选择器。
- Prewalk、顾问覆盖：`task.agentPrewalk`、`task.agentAdvisor`，支持沿用定义、开启、关闭和指定目标。
- 请求次数软上限：`task.agentSoftRequestBudget`；这是模型请求次数，不是费用金额。
- 服务等级：`task.agentServiceTierOverrides`，根据最终模型和服务商能力展示适用选项。
- 上下文压缩阈值：`task.agentCompactionThresholdOverrides`，支持原生 token 数或百分比形态。
- 专属账号池：`task.agentAccountPools`，按服务商选择允许的 OAuth 账号；显式空池代表不允许使用账号，不能退回 API Key 绕过限制。

这些设置按 Agent 精确名称匹配。保存定义或持久覆盖通常影响后续任务，不应宣称会立即重写运行中子代理的提示词、工具和模型；运行中 Agent 的临时切换应另行标明。

### 3.5 默认模型与角色绑定

这是核心配置页，不应只做一个“默认模型”下拉框。

**默认主模型保存在 `modelRoles.default`，不存在需要另造的 `defaultProvider` / `defaultModel` 配置对。** 当前会话实际模型、保存的默认模型、默认思考强度需要分别展示。

| 角色组 | 必须覆盖的原生 role ID |
| --- | --- |
| 主会话与工作用途 | `default`、`smol`、`slow`、`vision`、`plan`、`commit`、`task`、`advisor`、`widget` |
| 轻量与记忆 | `tiny`、`memory` |
| 专门能力 | `image`、`web`、`speech`、`dictation`、`judge` |
| 自定义 | 用户添加的其他 role，保留稳定 ID，允许中文展示名 |

每个角色需要：

- 查看全局绑定、项目覆盖、最终解析模型与来源；按 `modelRoleStorage` 提供适用的保存位置。
- 添加、替换、删除和排序多个候选，每个候选可带独立思考后缀。候选按顺序解析出可用模型，**不是同时调用多个模型，也不是请求失败后的故障转移链**。
- 支持 `@role` 引用和高级原始选择器，展示无法匹配、角色循环和模型类型不适用等结果。
- 清除本层绑定后预览继承或自动选择结果；未配置时不能保证所有角色都直接继承 `default`，也不能假造一个肯定可用的模型。
- 管理角色名称、颜色和在选择器中的隐藏状态，对应 `modelTags`；隐藏不是禁用角色。
- 区分“仅供当前会话使用”和“保存为角色绑定”。在原生模型管理流程中，保存默认角色通常还会切换当前会话，其他角色的修改不应顺带切换主会话。

角色需要按用途过滤模型类型，例如图片生成不能只展示 Chat 模型，语音合成与听写分别对应 TTS、STT。`tiny`、`memory`、`web`、`judge` 也有各自的候选能力规则，不能统一套一个 LLM 列表。

### 3.6 统一模型选择与模型详情

供会话切换、角色绑定、Agent 模型、顾问和故障转移等界面复用。

- 搜索模型 ID、名称和服务商，按服务商、模型类型和可用状态筛选；可查看最近使用模型。
- 显示当前选中模型，以及未认证、被禁用、超出允许范围、目录发现失败等状态。
- 详情展示能力、上下文、输出上限、思考档位、价格、来源及自定义覆盖，不用名称猜测能力。
- 普通选择保存明确的 `provider/model-id`；高级入口保留原生模式匹配、角色引用、思考后缀和上游路由选择器。
- 按字段与模型能力提供思考选项；保留 `minimal`、`xhigh`、`max`、`auto` 及继承的区别，不把不同含义压成同一档。不能无条件剥掉模型真实 ID 中的冒号后缀。
- 模型图标遵守现有品牌规则；未匹配品牌时使用 ID 首字符的大写字母与稳定底色，不使用服务商图标冒充模型图标。

### 3.7 模型服务列表、连接与发现设置

- 浏览、搜索、新增、编辑、启用、禁用和删除服务配置，区分内置目录与用户覆盖。
- 基础连接包含服务商 ID、接口协议 `api`、`baseUrl`、自定义 `headers`、认证方式 `auth`、`authHeader` 和 API Key 来源。
- 不限于现有 Chat、Response、Message 三种展示；高级入口覆盖当前版本原生支持的 Google、Bedrock、Azure、Codex 等协议及专用 runner 类型。
- 管理自动发现类型与选项：Ollama、llama.cpp、LM Studio、OpenAI 模型列表、proxy、LiteLLM、Apple Foundation Models，以及超时和适用的 `injectV1`。
- 提供发现或刷新结果、失败原因、远端模型选择与手工新增入口；同步仅追加新模型，已有手工字段只有显式应用资料匹配时才更新。
- 模型资料仅按唯一 ID 或规范化别名匹配，不能把 OMP 选择器支持的模糊匹配误用于自动覆盖模型资料。
- 测试连接明确是否真实调用推理接口、使用哪个模型及可能产生费用；读取模型目录和真实推理测试不是同一动作。
- 删除服务配置与清除独立认证记录分开，不联动删除角色绑定而不提示。

### 3.8 认证与账号管理

- 显示认证来源、是否已配置及可用状态，支持 API Key 配置、受支持服务商的 OAuth 登录和退出。
- 支持多账号列表、账号限额信息、当前会话固定账号与解除固定；无法提供额度数据的服务商显示“不支持”，不填造数值。
- 编辑 `auth.accountPolicies` 中的服务商、账号匹配条件、优先级、配额预留和回收阈值。
- 账号池选择与 Agent 覆盖页关联；认证代理配置放在全局高级入口，项目不能重定向凭据。
- API Key 和请求头值可按原生语义使用字面值、环境变量引用或 `!command`；显示来源而不是自动求值，打开页面不应执行取密钥命令。
- 密钥默认遮蔽；分享、导出或配置预览不得自动包含凭据。登录失败、过期、取消和权限不足需要独立状态。

### 3.9 自定义模型与内置模型覆盖编辑

新增自定义模型与修改现有模型的 `modelOverrides` 是不同操作，需要分别表达原始目录值和稀疏覆盖值。

| 分区 | 必须可编辑的配置能力 |
| --- | --- |
| 身份与类型 | `id`、`name`、`api`、`kind`；模型定义层适用的 `baseUrl`、`headers` |
| 输入与工具 | `input`、`supportsTools`、`imageInputDecoder`、`imageCountBudget`、`tokenizer` |
| 上下文与输出 | `contextWindow`、`maxContextWindow`、`maxTokens`、`omitMaxOutputTokens` |
| 思考能力定义 | `reasoning` 与 `thinking`：`mode`、`efforts`、`defaultLevel`、`effortMap`、`supportsDisplay`、`requiresEffort`；读取旧形态时正确展示 |
| 费用与缓存 | 四项价格 `input`、`output`、`cacheRead`、`cacheWrite`，以及 `premiumMultiplier`、`promptCache`；区分未知价格与免费 |
| 传输与兼容 | `preferWebsockets`、`compat` 及适用协议选项 |
| 上下文后续处理 | `contextPromotionTarget`、`compactionModel`、`remoteCompaction` |

不要把“模型支持哪些思考控制”“角色选用哪个思考等级”“默认思考强度”“数值思考预算”合成一个字段。当前应用已有的 Message 数值预算也需保留，并校验与模型输出上限的关系。

### 3.10 高级协议与请求参数

- 在适用的服务商或模型下编辑 `compat`：消息角色、工具调用、严格工具、推理格式与映射、流式用量、超时、Responses 状态与配对、图像输入、缓存、路由和 `extraBody`。
- 覆盖条件分支 `whenThinking`，以及 Anthropic、Bedrock、OpenRouter、Vercel 等适用的协议专项；Bedrock 包含 guardrail、请求元数据和缓存控制。
- 支持原生网关传输、远程压缩等复杂对象，通过分组表单或 Schema 校验的结构化编辑器呈现，不只提供无法校验的任意文本框。
- 通用生成设置包括 `temperature`、`topP`、`topK`、`minP`、`presencePenalty`、`repetitionPenalty`、`textVerbosity`、`thinkingBudgets` 和适用的服务等级。
- 用“使用服务商默认值”表达原生哨兵值；按协议展示有效范围和不支持项。
- 角色本身保存选择器与思考后缀，不能杜撰通用的 `modelRoles.<role>.parameters` 来存所有采样参数。

### 3.11 模型预设

- 列出预设，预览与当前配置的差异；支持保存当前组合、覆盖确认、应用及删除可写来源的预设。
- 预设保存的是 `modelRoles` 与 `defaultThinkingLevel`，不是完整模型服务、账号或凭据备份。
- 显示全局、项目和其他覆盖来源；同名预设按最高层整份选择，不跨层拼接。
- 应用时按角色存储策略写入角色，展示未能覆盖的高优先级设置；不能只给“已应用”而隐藏未生效项。
- 项目来源不能通过原生全局删除操作移除时，引导编辑对应源文件；删除全局同名预设后，项目预设仍可能存在。

### 3.12 模型允许范围与快速切换

- 编辑 `enabledModels`、`enabledProviders`、`disabledProviders`，并支持其原生路径作用域规则。
- 编辑 `cycleOrder` 的角色成员与顺序；这是快速轮换的角色顺序，不是模型目录排序。
- 编辑 `modelProviderOrder`，与默认模型、账号优先级分开。
- 明确空模型允许列表表示不额外限制；非空列表完全匹配不到时是真正无可用模型，不能偷偷退回全部模型。

### 3.13 故障转移策略

- 为角色、具体 `provider/model-id` 或 `provider/*` 配置 `retry.fallbackChains`。
- 对候选执行添加、替换、删除、排序和思考等级编辑，区分原始规则与实际解析目标。
- 配置是否启用、触发错误类型、重试次数、最大等待、配额重置等待，以及何时切回主模型。
- 配置基于剩余额度的提前切换、预留比例和触及预留后的处理策略。
- 与角色的有序解析候选分开显示；角色切到项目存储，不代表原生故障转移编辑也自动写入项目。

### 3.14 Agent 通用运行设置

保留按领域分组、搜索、条件显示和恢复默认的完整设置入口，不把“Agent 设置”缩减为子代理提示词编辑。

| 设置领域 | 原型应覆盖的能力 |
| --- | --- |
| 模型与提示 | 默认思考、采样、回复风格、系统提示相关配置、模型与工作区信息注入、Prewalk、顾问、循环保护 |
| 交互与会话 | 队列、继续会话、输入补全、审批、通知、启动更新、语音、协作等非 TUI 专属行为 |
| 上下文 | 工作区与附加源、压缩阈值、保留量、压缩模型、视觉压缩、TTSR 规则 |
| 记忆 | 后端选择、自动学习、归档与检索，以及当前版本支持的本地记忆、Mnemopi、Hindsight 等专项 |
| 文件与 LSP | 读取和摘要、编辑方式、格式化、诊断、语言服务器及相关限制 |
| Shell 与代码执行 | Bash、PTY、超时、后台执行、Eval 和 Python/JS 运行时配置 |
| 子任务与隔离 | 并发、递归深度、运行时限、软请求上限、结构化输出、完成探测、工作树、沙箱与合并策略 |
| 工具与扩展 | 工具启停、Todo、搜索、浏览器、桌面控制、MCP、扩展包、技能和自定义命令的配置与发现来源 |
| 服务与隐私 | 服务商协议、检索、缓存、本地小模型、语音服务、超时、并发限额、隐私及适用凭据 |
| 高级与内部 | 没有专门控件但原生支持的数组、映射、路径规则、覆盖表和其他设置，不因 UI 没有分组就漏掉 |

设置类型至少需要开关、枚举、数值、单行和多行文本、可排序列表、映射及嵌套对象编辑。字段和选项以实际 OMP 版本的注册元信息、Schema 与原生验证为准，不照搬 HTML 原型中的样例默认值。

应用已有的“新会话默认免审批”仍属于宿主持久设置；会话内免审批只控制工具审批，不能自动回答普通提问，也不能被本页的全局权限项混淆。

### 3.15 顾问配置

- 提供与原生顾问配置对应的列表和详情，支持项目、用户来源及独立 `WATCHDOG.yml` 配置，而不只提供一个 `advisor.enabled` 开关。
- 编辑共享指令和共享建议数上限；每位顾问可设置名称、启用状态、模型、允许工具、专属指令、审查模式、间隔、同步积压策略和建议数上限。
- 区分保存的启用状态与当前运行、暂停、无模型、配额耗尽或错误状态。
- 与 Agent 定义中的 `advisor`、每 Agent 的顾问覆盖、`modelRoles.advisor` 保持关联，但不能将四者当成同一份配置。

### 3.16 高级配置与来源查看

- 提供设置项详情：原生键、类型、原生默认值、本层值、有效值、来源文件及覆盖关系。
- 对 `config.yml`、`models.yml`、Agent Markdown 和顾问配置提供适用的原始或结构化编辑入口；支持语法、类型和原生语义校验。
- 保存时保留未知字段和未编辑内容；不把无法识别的配置显示成空白默认值后覆盖掉。
- 支持重新读取外部修改，展示冲突、解析失败、只读来源和保存失败；重载失败时保留最后有效状态与用户草稿。
- 对不同字段保留未设置、`null`、`false`、`0`、空字符串、空数组及空映射的区别；并非每个字段都允许这些值，也不能统一用 `null` 表示清除。
- 提示实际生效时机：当前立即生效、下一轮、后续子任务或需重新加载；不统一承诺全部热更新。

## 4. 原型必须画出的状态与交互

- **初始和空状态**：无项目、无模型服务、无可用模型、无自定义 Agent、搜索无结果。
- **加载与生成**：目录发现、模型同步、登录、连接测试、AI 生成 Agent；使用标准 Material 3 进度组件，支持取消适用操作。
- **错误**：网络或认证失败、模型不匹配、角色循环、配置无效、只读、写入失败和被上层覆盖；原因应定位到相应对象。
- **破坏性操作**：删除定义、删除服务、退出账号、覆盖预设、批量重置需显示影响范围；清除覆盖后可能露出的下层配置也要可理解。
- **编辑状态**：未保存、保存中、已保存、保存但未生效、冲突；离开复杂编辑页前处理未保存内容，切换项目或容器不丢失或串用草稿。
- **返回导航**：从模型选择、账号、来源详情等子页面返回时，恢复原页面滚动、展开和选中位置。

视觉继续沿用现有白底 Material 3、中文 UI、Material Symbols 和非线性过渡。列表采用“图标 + 标题 + 必要副标题”，菜单采用“图标 + 标题”；复杂帮助放进详情，不用大量小号说明文字堆满主列表。本次不另定配色、布局或动效规范。

## 5. 原生能力与原型补充的界线

| 能力来源 | 设计时如何处理 |
| --- | --- |
| TUI 已有管理能力 | `/agents` 的发现、禁用、模型与 Prewalk/顾问覆盖、AI 生成；`/models` 的角色、循环、预设、故障转移和刷新；普通设置及相关账号、顾问入口，应保持语义一致 |
| 配置文件已有、TUI 未提供完整表单 | Agent 全字段手工编辑、复制和删除，自定义服务与模型完整 Schema、高级协议对象等，需要 GUI 补足，不能声称原生 `/agents` 已经提供完整 CRUD |
| GUI 独有的表达 | 作用域对照、覆盖结果、差异预览、来源详情和结构化编辑，用于解释真实配置，不创造 OMP 不支持的存储层或参数结构 |
| 不属于本页的 TUI 外观 | 终端配色、状态栏分段、终端键位和 TUI 光标等不照搬到 GUI；应用外观仍留在宿主设置，不回写 TUI 配置 |
