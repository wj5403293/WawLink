WawLink verified binary inputs and rootfs builder
==============================================

Commands (run from the repository; neither command uses sudo or Docker):

  ./scripts/fetch-android-binaries.sh
  ./scripts/build-debug-rootfs.sh

The first command provisions native executables/dependencies and the official UI
fonts. It never executes downloaded Android executables. Python3, flock and
dpkg-deb are required. Fonts are committed; generated native binaries are excluded
from source control. The command recreates missing inputs and rejects wrong
SHA256 values.
The locked PRoot package uses the Termux-listed Librehat mirror because the
primary repository no longer retains that version; its original SHA256 is kept.

The second command requires Linux x86_64 or arm64, Bash, Python3, curl, GNU tar,
sha256sum, sha512sum, dpkg-deb, flock and normal GNU coreutils. Static QEMU and zstd
are used from PATH when present; missing tools and dependencies are unpacked from
Debian's official bookworm repository into build/host-tools without root.
Host PRoot is always provisioned from pinned compatible inputs: official static
PRoot5.5.0 on x86_64, Debian5.4.0-3 on arm64. Old system PRoot5.1 is never selected:
it mishandles modern access syscalls and makes Noble dpkg falsely report its own
database as unwritable. Only the aarch64 guest QEMU binary is retained from
qemu-user-static. See assets.lock.json for versions, URLs and SHA256 values.
Host libraries are under usr/lib/<host>-linux-gnu. The pinned dependency baseline
is glibc2.34 on x86_64 and glibc2.38 on arm64. Unsupported hosts fail explicitly.

Build behavior
--------------
Ubuntu Base 24.04.4 arm64 is downloaded directly from cdimage.ubuntu.com and checked
against both the pinned SHA256 and the current official SHA256SUMS file. Bun1.3.14,
Node22.22.2 and the OMP18.12.6 npm tarball have fixed upstream integrity values.
Ubuntu packages are authenticated by apt using the included Ubuntu archive
keyring. Tsinghua ubuntu-ports is used; HTTP is only used for signed apt bootstrap,
then changed to HTTPS after CA certificates are installed. The build requires
network access to these origins and npm's registry for OMP production dependencies.
No local user authentication, providers or credentials are copied into the image.

All initialization runs in proot; x86_64 hosts additionally use qemu-aarch64-static
with QEMU_CPU=max. PROOT_NO_SECCOMP=1 supports hosts with restrictive tracing rules.
Host builds deliberately use real hardlinks, not --link2symlink. The upstream
extension can embed absolute host staging paths in .l2s links; these break dpkg
self-upgrades and cannot survive renaming/extracting the portable rootfs archive.
Android's runtime-specific link2symlink setting is independent of host construction.
Bun is installed from the official arm64 Linux binary, Node includes npm/corepack,
and OMP is extracted from the integrity-pinned npm package with its complete
production and optional dependency graph. No standalone fake CLI is substituted.
Installation uses bun install --omit dev so a missing published lockfile is saved;
--production would imply frozen-lockfile and skip writing it. bun pm trust --all
then executes the real blocked native dependency postinstalls using that lock.
The exact manual Node distribution is marked in
/usr/local/share/wawlink/preinstalled-node (v22.22.2), allowing the runtime to
uninstall that known distribution without pretending apt owns /usr/local/bin/node.
Git, curl, CA certificates, rg, fd, jq, unzip, xz, zstd and Python are installed.
Build-only C/C++ tools are removed afterward. Apt, Bun and npm caches are cleaned;
package licenses, OMP native modules and the generated dependency lock remain.

The image contains a real /workspace JavaScript project and safe configuration:
  /root/.omp/agent/config.yml: tools.approvalMode = always-ask
  /root/.omp/agent/models.yml: providers = {}
The app/provider UI must configure a real provider before an authenticated model
request. No auth.json or dummy API key is generated.

The script executes actual bun/node/omp/git/rg/fd/jq/xz/zstd version checks before
publishing .wawlink-ready. A failure leaves only ubuntu-main.partial and exits
nonzero; it cannot masquerade as a completed image. The completed tree is retained
at build/debug-rootfs/ubuntu-main. An unchanged ready tree is reused and can be
repacked. Existing trees with different/incomplete inputs are never deleted: move
such a tree aside explicitly before rebuilding. Only the script-owned .partial
directory is removed on a subsequent attempt; its downloaded apt archives are
first preserved in build/downloads/ubuntu-apt and copied into the fresh staging
tree, where apt still validates their hashes. Concurrent builds are serialized.

A successful build atomically writes:
  build/outputs/ubuntu-main-debug.tar.zst
  build/outputs/ubuntu-main-debug.tar.zst.sha256
  build/outputs/ubuntu-main-debug.tar.zst.sizes.json

The final console report and sizes.json contain the real extracted and archive
byte sizes and MiB values. There is deliberately no 150–220MB cap: complete runtime
functionality takes precedence. No claimed final size is available until the
builder has actually completed. No emulator/device or Docker is involved.

APK and Rootfs are independent deliverables. Build the APK after provisioning
native inputs with ./gradlew :app-android:assembleDebug; no Rootfs archive is
required or embedded. Transfer ubuntu-main-debug.tar.zst to the device and select
it under the container page's Rootfs import tab. Startup never unpacks an APK
asset. Installing a same-signature APK update preserves existing containers;
an unchanged Rootfs does not need to be downloaded or imported again.

Signed Release APK (independent of Rootfs):
  ./scripts/build-release.sh [vMAJOR.MINOR.PATCH]
This provisions the same pinned native inputs and builds with JDK 17, Platform 35,
Build Tools 35.0.0 and NDK 27.0.12077973. ANDROID_HOME/ANDROID_SDK_ROOT overrides
the default ~/Android/Sdk. The version defaults to 0.1.2; versionCode is
1000000 + major*1000000 + minor*1000 + patch (minor/patch 0..999, Android code limits apply).
The separate sign-release.sh reads ~/.android/wsdx233.keystore, alias wsdx233,
and WSDX233_KEY_PASSWORD from the trusted ~/.android/.env or process environment.
Keep both private files mode 0600; never commit or print their contents.
WSDX233_KEYSTORE_PATH can override the local keystore path. Both store and key
use the supplied password. No signing credentials are passed to Gradle.
Output: app-android/build/outputs/apk/release/app-android-release.apk and
app-android-release.apk.sha256 in the same directory. The signer checks the
pinned certificate, APK signatures and alignment before replacing outputs.
--unsigned builds only the unsigned intermediate APK for the isolated CI job.
Direct Gradle assembleRelease also produces an unsigned, non-installable APK.

.github/workflows/android-release.yml runs only on vMAJOR.MINOR.PATCH tag pushes.
Both Android setup steps install platform-tools explicitly rather than the removed
legacy tools package; the required platform, build tools and NDK remain pinned.
Separate build/sign/publish runners isolate the release Environment's
WSDX233_KEYSTORE_BASE64 and WSDX233_KEY_PASSWORD secrets from Gradle and the
publishing token. The release Environment allows only v* tags. Only explicit
APK/checksum files are uploaded; the temporary key is deleted, never cached.
See README.md for tag publication, environment setup and version constraints.
The current Debug certificate differs: Android cannot install this Release over
that Debug package. Back up exportable data before switching; uninstalling
removes app-private data, and a Rootfs export is not a full application backup.

Android refreshes guest /etc/resolv.conf from the active default network before
starting/executing commands and on live DNS changes. Offline periods retain the
last valid configuration; explicit /etc or /etc/resolv.conf bind mounts take
precedence. Existing archives with the builder's systemd stub DNS are fixed at
runtime and do not need to be imported again. New images keep portable fallback
DNS instead of the build host's stub resolver. Since Bun snapshots DNS servers,
OMP restarts and resumes the same session on the next idle send after a DNS
change, without interrupting an active task or automatically retrying a request.

Archive extraction preserves native hardlinks where allowed. If the filesystem
rejects hardlinks, it materializes regular files with the original permissions
and modification times instead of substituting symlinks. Such files no longer
share an inode and can require additional storage; archive path checks still apply.

Android native integration
--------------------------
The five official Proroot files from coderredlab/andClaw 2.3.47 are unchanged:
  libproroot.so
  libproroot-runtime.so
  libproroot-bridge.so
  libproroot-linker.so
  libproroot-stub-loader.so

Pinned source: https://github.com/coderredlab/andClaw/tree/376460cc8e76f1652f51493de5180daceecb78c7/app/src/main/jniLibs/arm64-v8a
The version label identifies this upstream application snapshot, not a standalone
Proroot release. Each file's URL and SHA-256 are pinned in assets.lock.json.
License: proprietary, free to use in projects; modified binary redistribution is
not allowed. Proroot-upstream-notice.txt preserves the full pinned upstream notice.
The app MUST disable native stripping (keepDebugSymbols **/*.so) and package all
five side-by-side. Invoke libproroot.so -r ROOTFS -0 -w /workspace with explicit
host:guest bindings, including -b /dev:/dev -b /proc:/proc -b /sys:/sys.
Set PROROOT_TMP_DIR=appDataDir/tmp and select the matching installed components:
  PROROOT_LIB_PATH=nativeDir/libproroot-runtime.so
  PROROOT_LINKER_PATH=nativeDir/libproroot-linker.so
Do not rely on automatic component selection or retain paths from an older APK.
Do not use the obsolete libproroot_hook.so name or fictitious PROROOT_ROOTFS API.
The runtime library uses guest glibc; do not load it with Android System.loadLibrary.

Termux packages provide genuine Android aarch64 proot, its loader, libtalloc and
libandroid-shmem. For proot, set PROOT_LOADER=nativeDir/libproot_loader.so and
LD_LIBRARY_PATH=appDataDir/proot-libs:nativeDir. Create libtalloc.so.2 in that private
alias directory as a symlink to the installed nativeDir/libtalloc.so; refresh the
target after APK updates. This satisfies the original SONAME without copying or
patching native binaries and respects Android's lib*.so extraction rule.
Do not set LD_PRELOAD for PRoot: its first guest program is linked against glibc,
not Android's loader. The guest bootstrap uses env -i before applying guest-only
environment settings. There is no 32-bit loader in the arm64-only APK.

The native zstd CLI is named libzstd.so to allow Android executable extraction;
its separate shared library is libzstd_shared.so (original SONAME libzstd.so.1).
Preload absolute libzstd_shared.so, liblzma.so and libz.so paths when invoking the
zstd CLI. Those preserve SONAMEs liblzma.so.5 and libz.so.1 unmodified. libzstd.so
is an executable, not a library for System.loadLibrary. No patchelf is applied.

Termux package checksums/versions are pinned in assets.lock.json; exact copied
binary SHA256 values and sizes are in composeResources/files/native-binaries.json.
Original package license notices are in composeResources/files/native-licenses.
The archives remain cached in build/downloads, and extracted packages under
build/vendor/termux preserve all upstream notices/source references.

Font provenance
---------------
Official Noto Sans SC variable TTF, JetBrains Mono Regular TTF and Material Symbols
Rounded variable TTF, with exact icon codepoints and license notices, live under
agent-ui/src/commonMain/composeResources/{font,files}. Names are:
  noto_sans_sc.ttf
  jetbrains_mono.ttf
  material_symbols_rounded.ttf
  material_symbols_filled.ttf
  files/material_symbols_rounded.codepoints

The filled font is a deterministic static instance of the original Material
Symbols variable font: FILL=1, GRAD=0, opsz=24, wght=400. It was created with
fontTools4.61.1 with recalcTimestamp=False. It is committed, so fontTools is not a
normal download prerequisite. Regeneration of a missing filled font requires
python3 fonttools==4.61.1; a byte mismatch fails explicitly. Original source URLs,
revisions, SHA256s and the derived-font axes are in font-provenance.json and
scripts/assets.lock.json. Noto/JetBrains licenses are OFL; Material Symbols is
Apache2.0. Icon names must be converted to the supplied codepoints, never rendered
as visible fallback strings or emoji.

Interactive terminal and code viewer sources
-------------------------------------------
The Android terminal-emulator and terminal-view modules are ported directly from
Love2Droid commit df583461887340a1031bfbf7b4fb6ee377750561:
https://github.com/wsdx233/Love2Droid/tree/df583461887340a1031bfbf7b4fb6ee377750561
They are the Apache-2.0 terminal-module exceptions from Termux v0.118.0, not the
surrounding application. terminal-emulator/NOTICE records the source chain and
local transport/JNI changes. The complete license is in licenses/ and the module
assets. libtermux.so is built from this source with the Android NDK for arm64-v8a;
it is not one of the unmodified prebuilt command executables listed above.

Desktop uses unmodified JediTerm 3.63 (Apache-2.0 selected from its upstream dual
license) and pty4j 0.13.4 (EPL-1.0) Maven dependencies. Their full licenses and
source locations are retained in licenses/ and app-desktop desktop resources.

Code highlighting uses Highlights 1.0.0 (Apache-2.0). Android fullscreen readonly
code uses Sora Editor 0.23.6 (LGPL-2.1-or-later); Desktop uses RSyntaxTextArea 3.6.0
(BSD-3-Clause). These dependencies are unmodified. Exact Maven coordinates,
tagged complete-source download URLs, license SHA256s and full license texts are
in agent-ui/src/commonMain/composeResources/files/code/ and are bundled as UI
resources. Sora copyright remains with Rosemoe. Replacing its dependency version
in agent-ui/build.gradle.kts and rebuilding the published project sources relinks
the application; no proprietary replacement library or WebView shim is included.
